# 0001 从模糊意图到可验收请求

- 日期：2026-11-05
- 场景：和 AI 对话，目标是改进自己提问的方式
- 产出：本地工具 qdoctor（体检 / 复盘 / 统计）

## 背景

起点只有一句话：

> 我在对话时无法用问问题得到自己想要的答案，这个项目就是用来优化我的问题的。

这是真实的起点：有方向、有痛感，但没有场景、没有验收。它本身就是一个“缺槽位”的样本。

需要先说清楚：**低分不代表想法差**。qdoctor 量的是“对方能不能据此行动”，不是“这个方向值不值得做”。这句话作为方向是好的，作为请求还不够。

## 用工具体检这次对话

| 输入 | 分数 | 说明 |
|---|---|---|
| “我在对话时无法用问问题得到自己想要的答案……” | 32/100 | 缺背景、约束、输出、验收、受众、示例 |
| 补齐目标/场景/验收/输出/受众/示例后的版本 | 100/100 | 要素齐全 |
| “我想跟同事说他不回消息的事，怎么开口？” | 30/100 | 追问变成“环境/版本是什么”“报错原文是什么” |

第三行是这次最重要的发现：**工具只覆盖了“和 AI 对话”这一半**。同一套槽位遇到人际对话就失灵，不是措辞问题，是维度不对。

## 做对了什么

### 1. 把感受翻译成可验收的结果

原始说法是“得不到想要的答案”。追问后变成：

- 形态：CLI + 本地网页，共用一套规则；
- 验收：自动化测试通过、契约校验通过、浏览器无控制台错误；
- 输出：分数、槽位诊断、追问清单、七段式改写稿。

“我想要更好的对话”无法验收；“每次对话后能复盘出至少一个改进点”可以。

### 2. 先定载体，再抠细节

第一轮只问两件事：交付形态（skill / 工具 / 手册 / 先诊断）和有没有真实案例。

载体没定时，讨论“用哪个框架”“槽位怎么设”都是浪费。

### 3. 给带代价的选项

不是问“你到底想要什么”，而是给 3-4 个选项，每个写清代价和推荐：

- skill：零依赖，但得先记得运行；
- 工具：能分享，但要定技术栈；
- 手册：最快，但靠自觉；
- 先诊断：最稳，但多一轮。

选择成本从“写一段需求”降到“点一个选项”。

### 4. 约束提前上桌

S 档、零第三方依赖、只推公司 Gitea、不自动提交、历史不存原文——这些不是实现细节，是方案边界。提前写死，后面就不用反复确认。

### 5. 用证据收尾

不说“应该没问题”，而是：

- `python -m unittest discover -s tests -t . -v` → 83 tests OK；
- `python tools/check_layers.py` → 依赖方向与第三方依赖通过；
- `python tools/blueprint_verify.py` → 12 项检查通过；
- Edge headless 实际打开体检/复盘/统计，无控制台错误。

浏览器检查还抓到“这段代码”被误判成“期望输出”的真实 bug，修规则并加了回归测试。证据不是装饰，它改变了实现。

### 6. 留下唯一的未知

最后没有假装知道“你的真实案例长什么样”，而是把它变成明确的下一步：5-10 个案例，原话 / 回答 / 本来想要什么。

## 漏了什么

我默认了“对话对象是 AI”，没有先问“和谁、什么场景”。直到用户补充“和人还有和 AI”才暴露。

这是 qdoctor 的“受众/场景”槽位缺失——**造工具的人和工具踩了同一个坑**。

教训：当对方说“对话”时，第一个问题应该是“和谁对话”，而不是“你想要什么工具”。对象不同，槽位就不同。

## 人际对话需要另一套槽位

| 维度 | 对 AI | 对人 |
|---|---|---|
| 目标 | 拿到答案或产物 | 让对方理解、行动、感受，或推进关系 |
| 背景 | 项目、环境、已尝试 | 关系史、对方处境、最近发生了什么 |
| 约束 | 版本、格式、篇幅 | 时机、场合、渠道、不能说的话、底线 |
| 验收 | 能跑通、符合格式 | 对方答应了什么、情绪是否缓和、下一步是否明确 |
| 风险 | 答错、幻觉 | 伤关系、失面子、把话说死、没有退路 |

- **AI 对话槽位**：目标、背景、约束、期望输出、验收标准、受众/用途、示例。
- **人际对话槽位（草案）**：目的、关系与背景、对方处境、时机与渠道、边界、期望结果、退路。
- **人际反模式（草案）**：立场代替需求、结论式提问、情绪高峰谈重要事、一次抛多个议题、不给台阶、用“为什么”追责。

草案没有直接实现，因为项目自己的规矩是“先用真实案例校准”。没有案例就定槽位，只是在拍脑袋。

## 可复用的三句话

1. 好问题不是一次问全，而是每一轮只问“下一步必须由对方决定的那一件事”。
2. 先定载体，再抠细节；先写验收，再谈方案。
3. 把“我不知道”留成明确的问题，不要用通用答案填满。

## 待补

- 5-10 个真实案例，至少一半是人际对话；
- 每个案例：原话 / 对方或 AI 怎么回 / 我本来想要什么 / 事后判断哪里偏了；
- 用途：校准 `qdoctor/rules.py`；设计 human 模式；脱敏后进 `tests/` 夹具。
